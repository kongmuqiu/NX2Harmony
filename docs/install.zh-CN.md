# 安装

[← 返回 README](../README.md) · [English](install.md)

在 Windows 电脑上，按下面的步骤，**你自己的**游戏文件会变成手机上一个签好名的鸿蒙应用，游戏数据也一并推到手机上。每个游戏第一次构建耗时较长，大部分时间不用管；之后再构建同一个游戏会复用已经准备好的数据，只重新打包和安装。各部分怎么配合见 [how-it-works.zh-CN.md](how-it-works.zh-CN.md)。AI 助手则照[安装 skill](../.claude/skills/install-nx2harmony/SKILL.md)（`/install-nx2harmony`）来做，它是本页的清单版。

开始之前：
- 游戏文件、密钥和固件：只用你自己导出的，来自你拥有的游戏和你拥有的主机。NX2Harmony 一样都不会去取，本页也不指向任何来源。
- 构建产出（HAP 和游戏数据）里就是游戏本身：只装在你自己的手机上，不上传、不给别人。
- 检查没通过时，提示里写着原因。要过这一关，办法从来不是改 `games.tsv`、后端的 `expected-*.json` 哈希文件或它的脚本。
- 软件的界面和提示都是中文，本页按你在屏幕上看到的写法引用。

## 需要准备什么

**一台电脑**：Windows 10 或 11，64 位（x64）。软件要放在本地磁盘上运行：放在网络共享或映射的网络驱动器上时，cmd.exe、CMake 和 ohpm 会失败或卡住（“环境”页会检查这一项）。

**磁盘空间**，指放游戏后端的那个盘（见[文件在哪](#文件在哪)）：游戏数据还没准备好时，王国之泪或宝可梦传说 Z-A 约 80 GB，时之笛约 70 GB；准备好以后 5 GB 就够。Docker Desktop 的镜像另存在它自己的磁盘镜像里，空间另算。

**一台鸿蒙手机**和一根 USB 数据线（见[准备手机](#准备手机)）。

**一个华为账号**：注册为开发者并完成实名认证。软件用它给每个游戏签名（见[签名](#签名)）。

**你自己的游戏文件**，按游戏：

| 游戏 | 版本 | 状态 | 文件 |
|---|---|---|---|
| 塞尔达传说 王国之泪（`0100F2C0115B6000`） | 1.4.3 | 已验证 | 本体：卡带 `.xci`（1.0.0，或已含 1.2.1 更新的卡带）、eShop 版 `.nsp` / `.nsz`，或 `.xcz`；NSZ 和 XCZ 在构建里自动解压。1.4.3 更新只收 `.nsz`（自己导出的 `.nsp` 可以先用 nsz 工具压缩成 `.nsz`）。`prod.keys`。 |
| 塞尔达传说 时之笛，Switch 2 版（`0400486024DEC000`） | v131072 | 优化中 | 含 v131072 更新的 `.nup`。`prod.keys`，取系统字体用。 |
| 宝可梦传说 Z-A，Switch 2 Edition（`0100F43008C44000`） | 2.0.2 | 优化中 | 含 2.0.2 更新（v393216）的 `.nup`。`prod.keys`，取系统字体用。 |

“已验证”：在手机上玩通过；“优化中”：能构建、能玩，帧率和个别画面还在调。完整的验证表见 [games.tsv](../games.tsv)。其他版本和游戏，以及标为“适配中”的版本，能识别、能显示，但不能构建。

**文件名。** 软件不用密钥，从文件自己的头部识别游戏，只有两处要看文件名：卡带镜像（`.xci` / `.xcz`）的文件名里要有方括号括起的 title ID，比如 `[0100F2C0115B6000]`；`.nsp` / `.nsz` 的版本取自文件名里的 `[v…]`，所以 1.4.3 更新的文件名要带 `[v720896]`。`.nup` 自己记着里面有什么。

**`prod.keys`**，从你自己的主机导出。放在 `%USERPROFILE%\.switch\prod.keys` 会被自动找到，也可以在软件里选它所在的文件夹（命令行用 `-k`）。软件从不复制它，也从不显示它的内容；只有要解密你的文件的步骤会读它。

**系统字体。** 每个游戏都向主机要共享字体。卡带镜像里带着，eShop 版和 NUP 里没有。软件用你的 `prod.keys` 从下面两处之一读一次：
- 游戏文件夹里你自己的一张游戏卡带镜像（`.xci`，不必是这个游戏的）；
- 你从自己主机导出并解开的固件（一个放 `.nca` 文件的文件夹），放在 `prod.keys` 所在文件夹里面或旁边，或在 `nx2h.local.json` 里写成 `"firmware"`。

读到后所有游戏共用。王国之泪用卡带 `.xci` 做本体时不用另外准备；`.xcz` 本体和 eShop 版一样，要有上面两处之一。

## 准备电脑

两种做法，检查的内容相同：
- **软件的“环境”页**：每一行是一项检查；「一键安装缺少的」用 winget 装好所有不需要账号的东西，「重新检查」再查一遍。需要你自己下载的那一行有「打开下载页」按钮。
- **从源码运行时，双击仓库目录里的 `一键安装环境.cmd`**（打包版没有这个文件，用“环境”页或 `nx2h.exe setup --fix`）：`where python` 找不到 Python 时，先用 winget 装 Python 3.12，并提示你关掉窗口再双击一次；之后做同样的检查和安装（`python nx2h.py setup --fix`）。微软商店的 `python` 别名也算“找到了”，所以如果 `python -V` 什么都不显示、打开了微软商店或提示找不到 Python，先自己在终端里运行 `winget install -e --id Python.Python.3.12 --source winget` 装好 Python，再双击一次这个文件。

缺少时会自动装的：

| 项 | 什么时候需要 | 怎么装 |
|---|---|---|
| Python 3.9 或更新 | 总要：运行后端的脚本（打包版自带的 Python 只给软件自己用） | `winget install -e --id Python.Python.3.12 --source winget` |
| Docker Desktop，并在运行 | 总要：Linux 工具在容器里运行 | `winget install -e --id Docker.DockerDesktop --source winget`；再点一次「一键安装缺少的」（或 `setup --fix`）会启动它，最多等 3 分钟。还没就绪就打开它看看，可能要先装 WSL 2 或重启 Windows |
| zstd | 时之笛（着色器清单） | `winget install -e --id Meta.Zstandard --source winget` |
| PowerShell 7 | 只在没有预编译 libopus、要自己编译时（`backends\prebuilt-ohos` 里自带一份，源码和完整包都有） | `winget install -e --id Microsoft.PowerShell --source winget` |
| Git | 只在从源码运行、参考仓库 totk-android 要克隆时 | `winget install -e --id Git.Git --source winget` |
| Java | 只在所用的 DevEco Studio 不带自己的 Java 时 | `winget install -e --id Microsoft.OpenJDK.21 --source winget` |
| totk-android 在固定提交 | 从源码运行时，克隆到 `backends\totk-android`（完整包自带一份） | 后端的 `native-harmonyos/upstream.py` |
| 登录华为账号 | 签名用；装好 DevEco Studio 后才提供 | 在浏览器里打开登录页 |

要你自己动手的：
- **DevEco Studio。** 「打开下载页」按钮会打开华为的下载页（https://developer.huawei.com/consumer/cn/deveco-studio/）。安装、登录华为账号，再打开一次，让它把 HarmonyOS SDK 下载完。和手机通信的 hdc 随它一起装好。装了几个时，用 SDK 最新的那个。
- **nxnative**（从源码运行、构建时之笛时）：把 [nxnative](https://github.com/seedds/nxnative) 克隆到 `backends\nxnative` 或本仓库旁边，检出 `backends/SOURCES.tsv` 记的提交；也可以在 `nx2h.local.json` 里写成 `"nxnative"`。游戏后端本身，NativeGames-harmonyos（王国之泪）、LZA（Z-A）、OOT（时之笛），就在仓库的 `backends\` 里；完整包把它们连同 nxnative 和 totk-android 都放在自己的 `backends\` 里。缺后端时，对应的游戏能识别，但不能构建。

打开软件：
- **打包版：** NX2Harmony 文件夹里的 `NX2Harmony.exe`：本仓库 Releases 页面上的完整包（`NX2Harmony-0.1.3-windows-x64-full.zip`，解压到任意位置），或打包后的 `dist\NX2Harmony`。整个文件夹是便携的，拷到哪里，设置都在 `data\` 里跟着走。旁边的 `nx2h.exe` 是命令行版。
- **从源码：** 装好 Python 3.9 或更新版本后，双击 `NX2Harmony.cmd`。第一次打开时会装 `requirements.txt` 里的 PySide6 和 cryptography（约 80 MB）。
- **自己打包：** 在装了 `packaging/requirements-build.txt` 里那些包（PyInstaller、PySide6-Essentials、Pillow、cryptography）的 Python 里运行 `python packaging/build.py`。结果在 `dist\NX2Harmony`，里面的 `data\` 重新打包时会保留。给一台全新电脑用的完整包：`python packaging/full_bundle.py --out <文件夹> [--zip]`（见 [how-it-works.zh-CN.md](how-it-works.zh-CN.md#完整包)）。

## 准备手机

1. 设置 → 关于手机：连续点几次版本号，直到打开开发者模式。
2. 设置 → 系统 → 开发者选项：打开 USB 调试。
3. 用数据线把手机连到电脑，手机上弹出提示时允许调试。

之后软件顶部会显示手机的型号和系统（没连手机时显示“手机未连接”），每 5 秒查看一次。一次只连一台手机：连着好几台时，软件不知道用哪一台（除非 `nx2h.local.json` 的 `"hdc"` → `"target"` 指定了一台）。DevEco Studio 开着自己的 hdc 服务时，软件也能在那里找到手机，并记住这个服务。

不用自己盯着屏幕：从签名开始到游戏打开，构建每 20 秒唤醒一次手机、让屏幕保持亮着；结束后（出错或按了「停止」也一样）手机恢复原来的息屏时间。游戏打开之前不要拔线。

给手机留出游戏数据的空间：王国之泪约 17 GB，Z-A 约 8 GB，时之笛超过 26 GB（光 RomFS 镜像就约 26 GB）。Z-A 第一次安装时，解包着色器还要临时多占约 7.5 GB，最后会删掉。

## 用窗口构建

打开 NX2Harmony，顶部有三页。

**游戏库**
1. 「游戏文件夹」→「更换…」：选放游戏文件的文件夹。它和所有子文件夹都会扫描 `.nsp`、`.nsz`、`.xci`、`.xcz`、`.nup`，一个文件夹里可以放多个游戏。
2. 「主机密钥 prod.keys」→「选择…」：选 `prod.keys` 所在的文件夹。游戏数据已经准备好的游戏不用它也能构建，但从你的文件里取图标要用它。
3. 每个游戏一张卡片，带图标和状态。图标先从你自己的文件里取。文件里没有图标的游戏，软件在扫描游戏库时（构建时也会）自动按 title ID 联网查 eShop 图标：先查图片服务 tinfoil.media，查不到再用社区 titledb 列表里指向任天堂 CDN 官方图标的链接，少数 Switch 2 游戏用任天堂官网上的图。发出去的只有 title ID（titledb 列表是整份下载后在电脑上查的）。图标存在软件的 `work\icons` 里（见[文件在哪](#文件在哪)）。放进新文件后点「刷新」重新扫描；还没有图标的游戏会出现「从网上取图标」按钮。
4. 选中游戏，点「构建游戏」。标题下面那行写着还缺什么，或者“游戏数据已准备好，构建只需重新打包”。`games.tsv` 里没有的游戏显示“未适配”，不能构建。

**构建**：这个游戏识别到的文件，以及「在哪里玩」（手机）。连着手机时「构建完装到手机并推送游戏数据」是勾上的；不勾时，构建到签名的 HAP 为止。「开始构建」开始，「停止」停止。页面上有每一段及其耗时、正在运行的步骤和它的工具输出的最新一行、进度条（推送数据时显示 GB 数和剩余分钟数）和构建日志。结束后，「打开 HAP 所在文件夹」和「打开日志文件夹」各一键打开。

**环境**：见[准备电脑](#准备电脑)。除手机和密钥以外还缺东西时，软件一打开就停在这一页。

一次构建做这些：
1. **准备游戏数据**：解包、改写游戏代码、翻译着色器。第一次时这一段最长。
2. **编译原生库**。
3. **打包 HAP**：签名、逐项审计，换上游戏图标。
4. **安装到手机**，并标记为游戏，让系统按游戏调度。
5. **推送游戏数据**：手机上已有的同一份会跳过。
6. 只在 Z-A 第一次安装时：**着色器种子**，见下。

之后游戏在手机上打开。第 1 段之前，这个游戏还没有签名、或签名里没有这台手机时，构建会先在后台申请签名（见[签名](#签名)）。

第 1 段按游戏分，以及第一次时哪些步骤久：
- **王国之泪：** 解开 1.4.3 更新、合并本体和更新的 RomFS（按 1.4.3 核对）、RomFS 补丁文件（含屏幕布局，见[已知问题](#已知问题)）、系统字体、着色器翻译器、改写游戏代码、客体数据、着色器种子（首次约 3 分钟）、第三方静态库。翻译器在从 mcr.microsoft.com 拉下来的 .NET SDK 容器里编译，代码工具在这台电脑上建一次的镜像 `nativegames-tools:1` 里运行。
- **宝可梦传说 Z-A：** 解开 NUP、改写游戏代码、运行时表、打包 RomFS、系统字体、着色器翻译器、客体库（含宽屏相机补丁）、游戏数据、第三方静态库。着色器种子在第一次安装后生成：应用在手机上启动一次，用游戏自己的解码器解包着色器（约 1 分钟），电脑拉回、翻译（约 1 小时）后把种子推回去，再删掉手机上的解包文件。
- **时之笛：** 解开 NUP、核对游戏模块、存成未压缩模块、改写游戏代码、运行时表、打包 RomFS（约 12 分钟）、系统字体、客体库（含帧步长、动态分辨率补丁）、游戏数据、着色器翻译器，然后九步着色器，全在电脑上：抽出全部着色器（约 10 分钟）、SPIRV-Cross、整份翻译（约 10 分钟）、校验、SSA 化（约 8 分钟）、测试时补翻的变体和共享内存改写（约 2 分钟）、任务 / 网格着色器译成 compute 内核、包装内核、打包种子；最后是 libopus / libvpx 和 dav1d（AV1 过场动画）。

产出已经在的步骤会显示“已有，跳过”。构建中关窗口会先问一句，确定后停止构建；已完成的步骤下次跳过。

## 用命令行构建

从源码用 `python nx2h.py`，打包版用 `NX2Harmony.exe` 旁边的 `nx2h.exe`，命令相同。

```
python nx2h.py setup [--fix]
python nx2h.py scan <文件夹>...
python nx2h.py build [<文件夹>...] [-k <prod.keys 所在文件夹>] [--game <title id>] [--tag <标签>] [--no-install] [--screen <宽>x<高>] [--progress json]
```

- `setup` 检查电脑和手机；`--fix` 用 winget 装能装的，和「一键安装缺少的」一样。
- `scan` 列出文件夹里的游戏和版本、每个游戏的文件和还缺什么。
- `build` 准备数据、打包签名的 HAP、安装、推送游戏数据，最后打开游戏。
  - 不给文件夹时弹窗让你选，并记住；`一键构建.cmd` 就是这样（它把参数原样传下去）。
  - `-k`：`prod.keys` 所在的文件夹（或文件本身）。不给时用上次选的，再没有就找 `%USERPROFILE%\.switch`；还缺又需要时弹窗问。
  - `--game <title id>`：文件夹里有不止一个可构建的游戏时必须给，否则构建停下并列出它们。王国之泪 `0100F2C0115B6000`，时之笛 `0400486024DEC000`，Z-A `0100F43008C44000`。
  - `--no-install`：只出签名的 HAP。华为账号里已经登记过手机时，不需要连手机；连着手机构建、签名时会登记这台手机。带 `--no-install` 时不会登记连着的手机，所以账号里一台手机都还没有时，签名会停下，提示 `这个华为账号还没有登记任何手机`。以后要装时，连上手机，去掉 `--no-install` 再运行同一条命令：复用已有的一切，然后安装、推送。
  - `--screen <宽>x<高>`：王国之泪的界面按哪块屏幕布局，比如 `2848x1320`（宽高顺序都行）。不给就问连着的手机。
  - `--tag`：HAP 的标签，默认 `nx2h-<日期>-<时间>`。HAP 在 `<后端>\artifacts\release\<标签>\totk-harmonyos-<标签>-signed.hap`，每个游戏都是这个格式。
  - `--progress json`：每行输出一个 JSON 事件，给图形前端读（见 [how-it-works.zh-CN.md](how-it-works.zh-CN.md#进度事件)）。

退出码：`0` 完成；`1` 因错误停下（最后一行 `[RED]` 说明原因）；`2` 参数不对，或选文件夹的弹窗被关掉；`130` 被中断（Ctrl+C）。

```
python nx2h.py scan D:\Games
python nx2h.py build D:\Games -k D:\keys --game 0100F2C0115B6000
```

## 签名

鸿蒙应用要签名才能安装，调试签名只对一个包名和登记过的几台手机有效。每个游戏有自己的包名，由软件生成：`nx2h.<本机>.<游戏>`，比如 `nx2h.uk3f9a2.totk`。中间一段由这台 Windows 算出来，所以窗口、命令行和打包版的每一份拷贝得到同样的名字；名字一旦生成，就记在 `nx2h.local.json` 的 `"bundles"` 里不再变。手机上的应用和它的存档都绑在这个名字上。

**后台签名（默认）。** 某个游戏第一次需要签名时，构建会在浏览器里打开华为账号登录页（也可以提前在“环境”页点「一键安装缺少的」，华为账号那一行做的是同一件事）。你登录后，软件自己完成：
- 为这台电脑生成一把密钥和一张调试证书（用 DevEco Studio 自带 Java 的 keytool），所有游戏共用；
- 把连着的手机加进你账号的设备；
- 为这个游戏的包名申请调试 Profile，带上你账号里的全部手机。

DevEco Studio 要装着，但不用打开。用的是 DevEco Studio 自动签名用的同一个服务；它不是公开文档里的接口，华为可能会改。旧 Profile 快过期、或不含连着的手机时，会自动重新申请。用 `--no-install` 时不加手机，Profile 只含账号里已有的手机；账号里一台都没有时，签名会停下（见[用命令行构建](#用命令行构建)）。

存放在 `%USERPROFILE%\.nx2h`，属于你这个 Windows 用户：`account.dat`（登录信息）和 `keys\key.dat`（密钥的密码）用 Windows DPAPI 加密，只有这台电脑上的这个 Windows 用户能打开；`keys\` 里还有密钥库、证书、各个 Profile（`profiles\<包名>.p7b`），以及 hvigor 解密密码用的 `material\`。

**在 DevEco Studio 里签（备用）。** 后台签名失败、而电脑上装了 DevEco Studio 时，软件生成一个小的签名工程 `%USERPROFILE%\.nx2h\signing\NX2H_<游戏>`（用户文件夹路径里有空格或中文等非英文字符时，改放 `<系统盘>\nx2h-signing\NX2H_<游戏>`），用 DevEco Studio 打开它，并停下显示「打开 DevEco Studio 签名」按钮。在 DevEco Studio 里：登录华为账号，File → Project Structure → Signing Configs，勾选 Automatically generate signature，OK；手机要连着。然后重新开始构建。这个工程是后端应用外壳的一份拷贝（同样权限的配置、外壳自己的源码和资源、hvigor 文件），不含游戏代码、编译出的库和游戏数据；DevEco Studio 签出来的文件放在 `%USERPROFILE%\.ohos\config`。

**构建期间**，后端的 `AppScope\app.json5`（包名）和 `build-profile.json5`（签名）会换成这个游戏的，打完立刻换回；原件暂放在后端的 `prepared\nx2h-stage\signing`，构建中途被停掉时，下次构建开始前先换回。

**不显示、不拷出。** 签名文件和密码只在软件进程里读：不打印、不写进日志、不拷出这台电脑、不进任何仓库。登录过程自己的记录 `%USERPROFILE%\.nx2h\login.log` 只记请求行和字段名，不记值。本项目从不发布 HAP、游戏数据或签名材料。

华为账号有数量上限：提示设备数量或调试 Profile 数量已到上限时，到 AppGallery Connect 的设备管理、Profile 管理里删掉不用的，再构建。

## 文件在哪

| 内容 | 打包版 | 从源码 |
|---|---|---|
| 设置：游戏文件夹、密钥文件夹、后端位置、包名、手机连接 | `data\nx2h.local.json` | `nx2h.local.json` |
| 日志，每步一个：`<日期>-<时间>-<游戏>-<步骤>.log` | `data\logs\` | `logs\` |
| 游戏图标 | `data\work\icons\` | `work\icons\` |
| 从你的文件里读出的系统字体，所有游戏共用 | `data\work\shared-fonts\` | `work\shared-fonts\` |

打包版的 `data\` 在 `NX2Harmony.exe` 旁边；那个文件夹不能写入时（比如放在 Program Files 下），改用 `%LOCALAPPDATA%\NX2Harmony`。从源码运行时这些都在仓库目录里，git 会忽略它们。

- **后端：** 完整包里在 `NX2Harmony.exe` 旁边的 `backends\`（totk-android、nxnative 和预编译库也在那里）；从源码时在仓库自己的 `backends\`（totk-android 克隆到这里，nxnative 也可以放这里）；或在 `nx2h.local.json` 的 `"backends"` 写的位置。那里记下的位置只要文件夹还在就会用，所以 0.1.2 以前用仓库旁边后端的检出会照旧用它们，删掉这一项才改用 `backends\`。
- **用你的文件做出的游戏数据**，几十 GB：在各个后端的 `prepared\`。编译出的库、着色器翻译器和 HAP：在它的 `artifacts\`。
- **某一步读游戏文件时**，王国之泪可能把它硬链接到一个单独的文件夹（后端的 `prepared\nx2h-stage`、软件的 `work\stage`，或文件旁边的 `.nx2h-stage`）；只有建不了硬链接的地方（exFAT、网络或虚拟机共享文件夹）才复制一份。这一步完成后就删掉。
- **签名和华为账号登录：** `%USERPROFILE%\.nx2h\`（见[签名](#签名)）。
- **`prod.keys`：** 你放在哪里就在哪里；放在 `%USERPROFILE%\.switch\prod.keys` 会被自动找到。
- **手机上：** 应用（`nx2h.<本机>.<游戏>`），以及它自己存储空间里（`/data/storage/el2/base/haps/entry/files`）的游戏数据：`game-v143/`、`game-za/` 或 `game-oot/`（运行时表、RomFS 镜像、字体），`android/shaders/<版本>/`（着色器种子），王国之泪还有 `android/extracted/v143/romfs-patches*/`（补丁文件和屏幕布局）。存档也在应用的存储空间里。

## 构建停下时

看最后一行以 `[RED]` 开头的输出。窗口里它在构建日志中，结束时的提示条也会指向它；命令行最后打印它。它说明哪里不对；某个工具失败时，它还写出那一步的日志，日志最后几行通常就是原因。改好后再点「开始构建」，或再运行同一条命令：产出已经在的步骤会跳过，构建从停下的地方接着走。

第一次构建要下载容器镜像（Docker Hub 的 `python:3.14`、mcr.microsoft.com 的 .NET SDK）和一些软件包。网络慢或不稳时，下载或建镜像可能中断；已完成的不会丢，网络好时再构建一次就行。一个镜像总共最多建四次，都不成功才停下；第三、四次换用别的 Debian 软件源。

| `[RED]` 这一行 | 怎么办 |
|---|---|
| `这些文件夹里没有已适配、可一键构建的游戏` | 运行 `python nx2h.py scan <文件夹>` 看识别到了什么。检查文件名（见[需要准备什么](#需要准备什么)），以及版本在不在 `games.tsv` 里。 |
| `找到不止一个可构建的游戏` | 加 `--game <title id>`（窗口会自己加）。 |
| `缺本体…`、`缺 1.4.3 更新 .nsz…`、`缺…的 NUP…` | 把提到的文件放进游戏文件夹，文件名里带上标签。 |
| `…盘剩余 … GB，准备…约要 … GB` | 清理那个盘，或把软件连同后端搬到空间够的盘。 |
| `需要 prod.keys` | 选它所在的文件夹（`-k`），或放到 `%USERPROFILE%\.switch`。 |
| `没有找到连接的手机` | 见[准备手机](#准备手机)；或者加 `--no-install` 只出包。 |
| `构建要用本机的 Python 3.9 或更新版本` | 在“环境”页装 Python，然后重新打开软件。 |
| `自动安装没成功：退出码 0x8A15005E…` | 电脑上有东西替换了 HTTPS 证书（加速器、杀毒软件的 HTTPS 扫描、代理），winget 的微软商店源不认。0.1.3 起软件只从 winget 社区源安装；用旧版本时，在终端里运行那一行写的命令（`winget install -e --id <包名> --source winget`），或者关掉这类扫描。 |
| `后台签名没成功` | 检查华为账号（开发者、已实名认证）后再构建，或在 DevEco Studio 里签（见[签名](#签名)）。 |
| `Docker 镜像 … 都没拉下来`、`… 建了 … 次都没成功` | 网络问题：过一会儿再构建。 |
| `…这一步要用 Docker Desktop` | 启动 Docker Desktop（“环境”页会装好并启动）。 |
| `本体是 eShop 版…不带系统字体` | 把你从自己主机导出的固件放在 `prod.keys` 所在文件夹旁边，或在游戏文件夹里放一张你自己的游戏卡带镜像（`.xci`，不必是这个游戏的）。 |
| `还没有参考仓库 totk-android`、`…不在固定提交` | 在“环境”页修复「参考仓库 totk-android 在固定提交」那一行，或在后端里运行 `python native-harmonyos/upstream.py --update`。 |
| `软件包自带的参考仓库 totk-android 缺失或不完整` | 把你手上那份完整包完整地重新解压到原处（或从本仓库的 Releases 页面重新下载）。 |
| `找不到…的后端` | 打包版：把你手上那份完整包完整地重新解压到原处。从源码：后端是仓库的一部分，用 `git checkout -- backends` 恢复。也可以在 `nx2h.local.json` 的 `"backends"` 里写它的位置。 |
| `缺 nxnative 仓库` | 把 nxnative 克隆到 `backends\nxnative` 或本仓库旁边，或在 `nx2h.local.json` 里写 `"nxnative"`。 |
| `抽出着色器要用 zstd 程序`、`编译 libopus 需要 PowerShell 7` | 在“环境”页安装。 |
| `…和 assets/expected-oot-v131072.json 对不上` | 不是 v131072 的游戏文件：检查 NUP。 |
| `HarmonyOS SDK 不完整` | 打开一次 DevEco Studio，等 SDK 下载完。 |
| `…里还有别的游戏文件，建不了硬链接…` | 把那个文件单独放进一个文件夹，或腾出提示的空间。 |
| `安装失败` | 检查手机：已解锁、空间够、允许了调试。手机上已有同一包名、但用别的证书签的应用（在 DevEco Studio 里签的，或用的密钥已从 `%USERPROFILE%\.nx2h` 删掉）时，要先卸载它；卸载前先导出存档。 |
| `手机上的着色器解包 15 分钟没结束`、`手机上没有生成 bnsh.pack`（Z-A） | 连着手机再构建一次。 |
| `<步骤> 失败（退出码 N），日志：…` | 打开那个日志，最后几行就是原因。 |

还解决不了？在本仓库用构建问题的表单开一个 issue。写上游戏和版本、Windows 版本、怎么运行的软件（打包版，或从源码运行及其提交号：`git rev-parse --short HEAD`）、手机型号和系统（顶部显示的那样）、`[RED]` 那一行，以及它提到的日志的最后几行。贴之前，路径里有你的 Windows 用户名的，先删掉那一段；手机序列号、华为账号和团队名、邮箱地址，以及包名中间那一段（`nx2h.***.totk`），都换成 `***`。不要附上 `prod.keys`、固件、游戏文件、HAP、游戏数据、签名文件或 `nx2h.local.json`。

## 已知问题

- **宝可梦传说 Z-A 是“优化中”：** 能构建、能玩，帧率和个别画面还在调。
- **时之笛是“优化中”：** 能构建、能玩，但测试中发现了 bug，不再标“已验证”。
- **第一次构建慢：** 耗时长的步骤见[用窗口构建](#用窗口构建)，光是 Z-A 的着色器翻译就要约 1 小时。之后再构建同一个游戏只重新打包和安装。
- **王国之泪的屏幕布局：** 屏幕比 16:9 宽出 1% 以上时，构建会按手机屏幕重新布局界面（HUD 贴到屏幕两边，背景和过场铺满）。它问连着的手机（或用 `--screen`）；没连手机时这次不做布局，HUD 先在中间 16:9，连上手机再构建一次就补上。这份布局只能推进应用自己建的文件夹，应用在「画面比例」为「全面屏」时启动才建它。全新安装时通常就是这样，布局会在同一次构建里推过去。如果输出说手机上还没有这个文件夹（设置里选了 16:9，或应用上次按别的屏幕尺寸启动），在应用设置里选「全面屏」、点一次「开始游戏」，再构建一次：只补发缺的文件。游戏设置「画面」里 HUD 选「居中 16:9」，就回到原来的布局。
- **着色器：** 种子可能缺少个别着色器，玩的时候会补上。从软件里把手机记下的缺失清单拉回电脑补齐，还在计划中，没有做（见 [DESIGN.md](DESIGN.md)）。
- **存档**在手机上应用自己的存储空间里。卸载应用会删掉它们，NX2Harmony 还不能备份或恢复存档（在计划中）。王国之泪启动页的“存档”页可以把存档导出成 zip，卸载前先导出。在另一台电脑上构建的包名不同，会装成另一个应用，存档也各自独立。
- **签名**用的华为服务不是公开文档里的接口；它变了的话，在 DevEco Studio 里签（见[签名](#签名)）。
- **下载：** 测速选最快下载源的功能（`nx2h/mirrors.py`）已经写好，但在全新电脑上实测之前是关着的。
- **一次只连一台手机**，软件要放在本地磁盘上运行（见[需要准备什么](#需要准备什么)）。
- 界面和提示只有中文。

## 卸载

**手机上：** 像其他应用一样卸载，或运行 `hdc uninstall <包名>`。包名写在构建日志里（`包名：…`），也记在 `nx2h.local.json` 的 `"bundles"` 里。应用的游戏数据和存档会一起删掉：先导出存档。

**电脑上：**
1. **软件：** 删掉它的文件夹，连同 `data\`（从源码运行的，删掉仓库目录，连同 `nx2h.local.json`、`work\`、`logs\`）；用过 `%LOCALAPPDATA%\NX2Harmony` 的也删掉。
2. **游戏数据：** 各个后端的 `prepared\` 和 `artifacts\`（用你的文件做出的几十 GB 数据和 HAP），或者整个后端文件夹（完整包里的 `backends\`）。
3. **签名：** `%USERPROFILE%\.nx2h`（密钥、证书、各个 Profile、保存的登录信息），用过的话还有 `<系统盘>\nx2h-signing`。DevEco Studio 自己签的在 `%USERPROFILE%\.ohos\config`。
4. **Docker：** 后端用到的镜像和卷，确认你别的东西不用它们之后：

   ```
   docker image rm nativegames-tools:1 python:3.14 mcr.microsoft.com/dotnet/sdk:10.0-noble-aot
   docker volume rm totk-venv
   ```

   后端自己的脚本可能还建了别的卷，`docker volume ls` 可以列出来。
5. **为构建装的工具：** 在 Windows 设置 → 应用里卸载，或用 `winget uninstall --id <ID>`，ID 见[准备电脑](#准备电脑)。DevEco Studio 和普通程序一样卸载。

**华为账号里**的调试证书、各个 Profile 和登记的手机还在；不再需要的话，到 AppGallery Connect 里删掉。

软件从不改动你的游戏文件、`prod.keys` 和固件，它们一直在你放的地方。
